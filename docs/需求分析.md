# 需求分析：ASPX/ASHX 挂马监控与自动处置工具（webshell-guard）

> 版本：v1.0　日期：2026-11-18
> 背景：实际案例 —— 服务器 `D:\wwwroot\colorpantone\Help\Show-S6.aspx` 被植入带「写任意文件 + cmd 命令回显」的一句话木马（编译产物经反编译可见 `Request["w"]/Request["t"]/Request["c"]` 逻辑）。需要一个常驻工具在网站目录旁实时看住 aspx/ashx 文件。

## 1. 目标

| 编号 | 需求 | 说明 |
|---|---|---|
| G1 | 实时监控 | 对指定网站目录下 `.aspx`、`.ashx`（可扩展 `.ascx/.asax`）的**新建、修改、重命名**事件秒级响应 |
| G2 | 挂马检测 | 检出两类威胁：① 后门/一句话木马（webshell）② 页面被注入恶意 iframe/script（挂马、暗链、跳转劫持） |
| G3 | 立即处置 | 检出后立即处置：默认**隔离**（移动到隔离区，保留取证），可选**直接删除**、仅告警三种模式 |
| G4 | 告警通知 | 处置后第一时间通过 webhook 推送（兼容钉钉/飞书/企业微信机器人及通用 HTTP webhook），失败自动重试 |
| G5 | 可运营性 | 结构化日志、告警历史落盘、配置文件驱动、误报白名单机制 |

## 2. 威胁模型

攻击者入侵路径通常是：上传漏洞 / 弱口令 / 旁站 getshell → 写入 aspx 一句话或篡改正常页面注入恶意代码。落地形态有三种：

1. **新增恶意文件**：目录里凭空多出 `.aspx/.ashx` 后门文件（最常见）。
2. **篡改既有文件**：在正常页面第 275 行这类不起眼的位置插入一段 `Request + Process.Start / FromBase64String + WriteAllText` 的代码（本案形态）。
3. **挂马注入**：正常页面被插入外部 `<iframe src="http://恶意域名">`、`<script src="http://...">`、`document.write(unescape(...))`、伪造跳转等。

因此检测必须同时覆盖「新文件」和「老文件被改」两种情形，不能只看新增。

## 3. 检测策略（三层叠加）

### 3.1 规则引擎（核心）
每条规则 = 正则特征 + 类别（webshell / 挂马）+ 权重。按评分制判定，避免单条弱特征误杀：

- **webshell 类特征**（示例，完整见 `internal/detector/rules.go`）：
  - `Process.Start` 与 `cmd.exe` 组合（命令执行）
  - `Convert.FromBase64String` 与 `File.WriteAllText` 组合（写文件后门，本案同款）
  - `Request[...]` 出现在含 `Process/WriteAllText/Eval` 的同一文件
  - `CSharpCodeProvider / Microsoft.CSharp`（动态编译后门）
  - `<%eval request(`、`ExecuteGlobal`、`Scripting.FileSystemObject + SaveToFile`
  - `ProcessRequest` 页面里出现 `EnableViewStateMac=false` 等降防配置叠加
- **挂马类特征**：
  - `<iframe ... src="http(s)://外部域名"`（非白名单域）
  - `<script src="http(s)://外部域名"`（非白名单域）
  - `document.write(unescape(`、`eval(function(p,a,c,k,e` 打包混淆
  - `window.location` 跳转到外部可疑地址、隐藏 iframe（`width=0/height=0/display:none` + 外链）
- **评分**：每条命中加分，总分 ≥ 阈值即判定为恶意；`Request[` 这类中性特征单独出现不判死，组合出现才高分。

### 3.2 基线对比
- 首次运行可建立基线（文件路径 + SHA256 快照）。
- 「基线文件被修改且命中规则」→ 高可信告警；「不在基线中的新 aspx」→ 中可信告警并强制过一遍规则引擎。
- 白名单：对确认干净的文件按哈希加白，永不再报。

### 3.3 定时全量兜底
实时事件可能漏（进程重启间隙、网络盘同步等），加一个周期全量扫描兜底（默认每 10 分钟，可配）。

## 4. 处置策略

| 模式 | 行为 | 适用 |
|---|---|---|
| `quarantine`（默认，推荐） | 立即把恶意文件移入隔离目录（保留原目录结构 + 时间戳命名），写入元信息（原路径、命中规则、哈希），防误删不可恢复 | 生产环境 |
| `delete` | 检出后立刻物理删除（需求原文「立马删除」） | 已确认不需要取证 |
| `alert` | 只告警不动文件 | 观察期/调规则 |

防抖机制：文件写入事件后等待 500ms 内无再次写入才检测，避免把写到一半的文件误判或漏判；同时设置大小上限（默认 5MB），超大文件跳过实时检测、留待全量扫描。隔离/删除动作记录到告警历史 JSONL，可审计、可回放。

## 5. 告警（Webhook）

- 触发时机：判定恶意并完成处置后。
- 格式：POST JSON，字段包含 `host、时间、文件原路径、处置动作、命中规则列表（含行号）、文件 SHA256、威胁类别`。
- 兼容性：通用 webhook 直接 POST；钉钉/飞书/企微机器人选择对应模板包装（markdown/text）。三者均要求较严格的请求体格式，实现上做成 adapter。
- 可靠性：失败指数退避重试 3 次；告警同时写入本地 JSONL 历史，webhook 挂了也不丢记录。
- 频控：同一文件 60 秒内不重复告警，防止攻击者高频改文件刷爆群。

## 6. 配置项清单（config.yaml）

```yaml
watch_dirs: ["D:/wwwroot/colorpantone"]   # 监控根目录，支持多个
extensions: [".aspx", ".ashx", ".ascx"]   # 监控扩展名
scan_interval: 10m                        # 全量兜底扫描周期
debounce: 500ms                           # 写入防抖
max_file_size: 5MB
score_threshold: 6                        # 判恶分值线
action: quarantine                        # quarantine | delete | alert
quarantine_dir: "./quarantine"
webhook:
  url: "https://..."
  type: generic                           # generic | dingtalk | feishu | wecom
baseline:
  enabled: true
  file: "./baseline.json"
ignore_dirs: ["App_Data", "bin", "obj", ".git"]
external_domain_whitelist: ["cdn.bootcss.com", ...]  # 挂马判断时放行的外链域
whitelist_hashes: []                      # 确认干净的文件哈希
```

## 7. 架构

```
main.go                     装配、信号处理、优雅退出
internal/config             配置加载/校验
internal/detector           rules.go(规则库) + detector.go(评分判定/基线)
internal/monitor            watcher.go(fsnotify实时) + scanner.go(周期全量)
internal/action             处置器：隔离/删除 + 告警历史
internal/notify             webhook + 4种adapter + 重试/频控
```

数据流：`fsnotify 事件 / 定时扫描 → 防抖 → 读取文件 → 规则评分 → 判定 → 处置(quarantine/delete) → webhook + JSONL 历史`

## 8. 边界与非目标（v1.0 明确不做）

- 不做内容修复（自动把挂马行抠掉风险太高，只做隔离+告警，人工恢复）。
- 不做加壳/混淆深度对抗（如新版冰蝎全程加密流量），V1 覆盖明文特征与文件级篡改；后续可加熵值检测。
- 不替代杀软：只看网站脚本目录，不做全盘 AV。
- Windows/Linux 双平台支持（路径分隔用 filepath 处理），目标环境为 Windows IIS。

## 9. 验收标准

1. 模拟写入本案同款一句话木马 aspx → 秒级检出、移入隔离区、webhook 收到含命中规则明细的 JSON。
2. 正常 aspx 注入一行 `<script src="http://evil.com/x.js">` → 判为挂马并隔离。
3. 误报治理：白名单文件修改不再告警；单条弱特征命中不触发处置。
4. `go build` 通过，Windows 服务方式常驻运行不崩，日志完整。
